# 에스파코 재고관리

알라딘(에이디피) 물류 대시보드를 그대로 옮겨 온 것입니다. 색은 파랑 계열로 바꿔 구별했고,
전에 시트에서 하던 마감 처리와 매칭 작업을 웹 화면으로 옮겼습니다.

이 저장소(`espaco-wms`)가 수집기입니다. GitHub Actions 가 하루 2회 사방넷에서 엑셀을 받아
BigQuery 로 넣습니다. 워크플로는 저장소 최상위 `.github/workflows/` 에 있어야 도니까
이 폴더가 저장소 루트여야 합니다.

웹앱(Apps Script)은 올리지 않습니다. 옆 폴더 `espaco-dashboard/` 에 로컬로만 두고
`clasp push` 로 구글에 바로 올립니다. `Code.js` 에 웹훅 비밀값이 평문으로 들어 있어서
깃허브에 올리지 않는 편이 낫습니다. 알라딘도 같은 방식입니다.

```
espaco-wms/         ← 이 저장소. 수집 스크립트 + GitHub Actions
  setup_bigquery.sql   BigQuery 테이블 만드는 SQL
espaco-dashboard/   옆 폴더. 로컬 전용, clasp 로 배포
```

## 알라딘과 달라진 것

| | 알라딘 | 에스파코 |
|---|---|---|
| 기본색 | 분홍·빨강 | 파랑 (`#345DA7` · `#3B8AC4` · `#4BB4DE` · 크림 `#EFDBCB`) |
| GCP 프로젝트 | `adp-wms-data` | `espaco-wms-data` |
| 마감 처리 | 시트 탭에서 손으로 | **일일정산 탭**에서 |
| 거래처·상품 매칭 | 시트 탭에서 손으로 | **기준정보 탭**에서 |
| 유효기간 | 없음 | **재고현황 탭**, `inventory_lot` 테이블 |
| 출고주소 | 없음 | 발주 수집 → 마감 화면 표시 → 등록 거래처만 저장 |

경고·부족·지연 표시는 알라딘과 같은 붉은 계열로 두었습니다. 그건 색이 곧 뜻이라 바꾸지 않았습니다.

## 화면 구성

대시보드 · 재고현황 · 수불일계표 · 재고변동표 · 거래처별 출고 · 미출고 · 일일정산 · 기준정보

### 재고현황
**모든 재고**를 보여주되, 유통기한이 있는 재고만 유통기한별로 줄을 나눕니다.
제품명 오름차순, 그 안에서 유통기한 오름차순이고, 유통기한이 없는 재고는 `없음`으로
그 제품의 맨 아래에 붙습니다. 실제로 106줄 중 31줄은 유통기한이 없었습니다.

`로케이션 구분명`이 `출고가능`인 수량과 그 밖(`불량`)의 수량을 나눠서 보여줍니다.
재고 0 숨기기, 검색, 6개월 안에 만료되는 것만 보기가 있고 맨 아래에 합계가 붙습니다.

유통기한 화면에 안 잡힌 상품은 재고조회(기본)에서 채워 넣어 빠지지 않게 합니다.

### 일일정산
오더코드 한 건이 한 줄입니다. 거래처그룹·거래처명을 그 자리에서 고치고, 마감을 누르면
BigQuery `order_logs` 로 넘어가고 목록이 비워집니다. 과거 마감분 거래처 수정은 서브탭에 있습니다.

거래처 자동 매칭은 이 순서입니다.

1. 주소가 거래처 마스터의 배송지와 딱 맞으면 → 그 배송지 (`등록됨`)
2. 주소는 처음인데 전화번호가 맞으면 → 그 거래처의 새 배송지 (`새 배송지`, 배송지 추가 버튼)
3. 둘 다 없으면 → 거래처그룹·거래처명 모두 `온라인`

`온라인`으로 남은 건은 마감할 때 주소를 BigQuery 에 넣지 않습니다. 한 번 오는 개인 주문 주소를
쌓아 두지 않으려는 것입니다.

거래처로 저장하는 방법은 두 가지입니다.

- **저장 체크** — 받는분 이름·전화번호·주소를 발주내역에 있는 그대로 새 거래처로 넣습니다. 거래처명을 따로 안 적었으면 받는분 이름이 거래처명이 됩니다.
- **찾기** — 이미 있는 거래처에 붙일 때 씁니다. 거래처명·배송지명·주소·담당자·전화번호로 검색되고, 고르면 거래처명과 그룹이 채워집니다. 일괄 지정 줄에도 같은 검색이 있습니다.

### 기준정보
- **상품** — 묶음명, 주요제품 체크, 안전재고. 재고에는 있는데 마스터에 없는 상품을 찾아 한 번에 넣는 버튼이 있습니다.
- **거래처** — 받는 곳 한 곳이 한 줄입니다. 한 거래처가 받는 곳이 여러 곳이면 거래처명을 같게 해서 줄을 여러 개 둡니다. 배송지명(본점·2호점)과 담당자를 적어 두면 나중에 물품 보내기 화면에서 그 이름으로 고를 수 있습니다.
- **세트** — 세트 한 건이 팔리면 구성품 수량으로 나눠 집계합니다.

마스터에 없는 상품은 사방넷 이름 그대로 나옵니다. 다만 주요제품 재고와 안전재고 경고 표는
지정된 것만 나오는 표라 목록에서 빠집니다.

## 설치 순서

1. **GCP 프로젝트** `espaco-wms-data` 를 만들고 BigQuery 를 켭니다. `setup_bigquery.sql` 을 실행합니다.
2. **서비스 계정** `github-actions@espaco-wms-data.iam.gserviceaccount.com` 을 만들고 BigQuery 데이터 편집자·작업 사용자 권한을 줍니다. Workload Identity 풀을 만들고 GitHub 저장소를 연결합니다.
3. **GitHub 저장소** `espaco-wms` 를 비공개로 만들고 **이 폴더를 저장소 루트로** 올립니다. Secrets 에 `SB_COMPANY_CODE`, `SB_USER_ID`, `SB_PASSWORD`, `SHEET_WEBHOOK_URL`, `SHEET_WEBHOOK_SECRET` 를 넣습니다.
   `.github/workflows/daily-collect.yml` 의 `PROJECT_NUMBER` 를 실제 프로젝트 번호로 바꿉니다.
4. **스프레드시트**를 새로 만들고 확장 프로그램 → Apps Script 로 들어가 스크립트 ID 를 확인합니다.
   `espaco-dashboard/.clasp.json` 의 `scriptId` 에 넣고 `clasp push` 합니다.
5. 스프레드시트를 새로고침하면 `📦 마감 처리` 메뉴가 생깁니다.
   **처음 한 번: 필요한 탭 만들기**를 눌러 시트 탭을 만듭니다.
6. 배포 → 새 배포 → 웹 앱으로 배포하고, 그 URL 을 GitHub Secrets 의 `SHEET_WEBHOOK_URL` 에 넣습니다.

## 수집 항목

하루 두 번(11:53, 20:57 KST) 도는 `daily-collect.yml` 이 사방넷에서 네 가지를 받습니다.

| 스크립트 | 사방넷 화면 | 넣는 곳 | 중복 처리 |
|---|---|---|---|
| `download_stock.py` | 재고 > 재고조회(기본) | `inventory_history` | 그날 파티션 통째 교체 |
| `download_stock_lot.py` | 재고 > **재고조회(유통기한)** | `inventory_lot` | 그날 파티션 통째 교체 |
| `download_inout.py` | 입출고내역 | `inout_log` | 날짜별 파티션 교체 |
| `download_order.py` | 발주조회 | 대기열 시트 → 마감 시 `order_logs` | 오더코드로 거른 뒤 대기열에 |

재고와 유효기간별 재고는 **그날 찍은 한 세트만** 남깁니다. 하루에 두 번 돌아도 그날 것이
최신 한 세트로 갈릴 뿐 쌓이지 않습니다. 덮어쓰기(`WRITE_TRUNCATE`)라 지우는 과정이 없어서
BigQuery 스트리밍 버퍼 제약도 걸리지 않습니다.

### 재고조회(유통기한) 화면 흐름

엑셀받기 팝업이 재고조회(기본)과 다릅니다. 기본 화면은 받을 열을 고르는 `전체선택` 체크박스가
있지만, 이 화면은 `[다운로드 범위 선택]` 라디오(전체 / 현재 페이지 / 선택 항목)와
`[다운로드 서식 선택]` 드롭다운뿐입니다. 둘 다 기본값이 우리가 원하는 값(전체 · 기본서식)이라
건드리지 않고 `받기`만 누릅니다.

`엑셀받기` 버튼에도 '받기'가 들어 있어서, 글자가 정확히 `받기`인 버튼만 골라 누릅니다.

## 아직 확인이 필요한 것

- **발주조회 엑셀의 주소 열 이름** — `process_and_upload.py` 의 `ADDR_COLS` 에 후보를 넣어 뒀습니다.
  첫 실행 로그에 `[발주조회] 엑셀 열:` 로 실제 열 이름이 찍히니 그걸 보고 맞추면 됩니다.
  `debug_menu_columns.py` 를 수동 실행해도 열 목록을 볼 수 있습니다.
- **유효기간별 재고 엑셀의 열 이름** — 화면 머리글이 상품정보 · 재고상태 · 유통기한 묶음이라
  실제 엑셀 열 이름은 첫 실행 로그의 `[유효기간별 재고] 엑셀 열:` 로 확인합니다.
  `LOT_COLS` 후보에 없으면 거기에 더하면 됩니다.
- **웹앱 접근 권한** — 지금은 알라딘과 같이 링크만 있으면 누구나 열 수 있는 설정입니다.

## 앞으로 할 것

- **물품 보내기 탭** — 거래처를 고르면 그 거래처의 배송지 목록에서 주소지·전화번호·담당자를 골라 보내는 화면.
  서버 쪽 준비는 `getVendorSites(거래처명)`, `getVendorNames()` 로 되어 있습니다.
- **알라딘에 유효기간 적용** — 에스파코에서 확인한 뒤 같은 방식으로 옮깁니다.
